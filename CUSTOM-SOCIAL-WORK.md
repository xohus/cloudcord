# Shared custom friends and connections — implementation audit

User scope: mobile (iOS/Android), desktop (Windows/macOS) and browser. Shared custom friend entries support user ID or manually entered username, display name, avatar, bio, badges and banner. Shared connection entries support Steam and other services, account identifiers and information. Clicking entries opens their detailed custom preview. No real Discord relationships or OAuth verification are created.

## Current changes

- Shared ProfileAppearance schema includes customFriends/customConnections; desktop inbound sharing uses this normalizer already and outbound sharing spreads profile fields.
- Mobile runtime workflow imports the same schema and adds typed settings fields; existing normalization handles publishing and reading.
- Normalization bounds entries, text, links, details and badges; strips unsupported fields including verified; rejects executable schemes and URL credentials; deduplicates stable entry IDs; preserves explicit empty lists for clearing and omission for legacy profiles.
- Tests cover round trips, non-mutation, unsafe URLs, limits, duplicate IDs and old profiles.
- Desktop/browser editors and ProfileSectionsAPI integration now render click-to-open friend/connection detail modals with safe links and badge/media fields; desktop TypeScript and browser builds passed.
- Native mobile editor/detail screens and profile-only JSX anchor are wired into generated FakeProfile code; UI imports stay lazy to avoid startup regressions. Device coverage of the anchor still needs verification.
- Existing website profile routes preserve the complete profile JSON without a field allowlist. Local SQLite integration tests passed round trips, token/owner checks on updates, clears and stale-revision rejection. Creation remains the existing self-declared owner model, not proof of account ownership. No backend permissions were broadened.
- Mobile identity/profile regression tests passed after social wiring. Actual generated mobile bundle/target-device validation and public release remain outstanding.
- User confirmed both automatic public fetching and manual customization/content selection. Both editors now include public account lookup, selected-content search and manual title/image/link/subtitle editing, including Roblox. Shared normalization preserves content items and fetch metadata.
- New backend provider module supports basic Steam, Roblox, GitHub and YouTube public profiles; Steam game search, Roblox universe-ID lookup and YouTube video-link selection. Mock provider tests pass after correcting exact Steam XML tag matching. Other providers remain manual-only. Backend deployment is outstanding, so the new fetch endpoints are not yet live.
- Roblox selection now accepts game links and fetches experience icons. YouTube accepts video-link variants with canonical deduplication and public text search (live search returned 19 results). Provider route tests cover safe error responses without leaking upstream payloads.
- Desktop/browser and mobile editors preserve in-flight edits, reject late results for removed entries or changed services/user IDs, reset searches on selection and guard search results against switching entries. Schema tests cover those merge rules. Native link failures now show an error instead of producing an unhandled rejection; image failures reset on URL changes.
- Latest browser and desktop builds passed. Mobile CustomSocial TypeScript check passed against native component types after fixing unsupported accessibility props. Generated editor comparison found no new diagnostics versus HEAD, but 19 inherited/local-overlay diagnostics remain; this is not a full-runtime or device validation.
